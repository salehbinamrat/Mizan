# ميزان الطبي — التشغيل دون إنترنت وعبر LAN سلكية

> الحالة في 17 نوفمبر 2026: توجيه إعداد العميل والهوية الأولية مضافان إلى فرع عمل قيد اختبار CI. هذا **ليس** مُثبت خادم متكاملا. لا تدخل بيانات مرضى أو بيانات مالية حقيقية قبل اجتياز اختبارات Windows وPostgreSQL واختبار الاستعادة في المستشفى.

## 1. وضع الجهاز الواحد — دون إنترنت

1. استخدم جهاز Windows مخصصا يحتوي على خادم API وقاعدة PostgreSQL محلية؛ يفضل خادم افتراضي أو جهاز مستقل مع UPS.
2. ثبت .NET 10 وPostgreSQL 17 ومكونات البرنامج من ملفات معتمدة مسبقا. لا تحتاج إلى Wi-Fi ولا اتصال إنترنت وقت التشغيل.
3. اضبط `MIZAN_DB_CONNECTION` ليشير إلى `127.0.0.1:5432`، وشغّل API المحلي مع `ASPNETCORE_URLS=https://localhost:5081` بعد إعداد شهادة موثوقة.
4. شغّل Windows client على الجهاز نفسه، واختر «إعداد اتصال الخادم» ← «جهاز واحد» ← فحص الاتصال ثم حفظه.
5. عند إنشاء أول قاعدة فارغة، يعرض الخادم التفاعلي رمز التهيئة مؤقتا. أدخل الرمز واسم المستشفى واسم المسؤول واسم الدخول وكلمة المرور (12 حرفا على الأقل). بعد إنشاء الحساب يعاد عرض تسجيل الدخول.

**هام:** «دون إنترنت» يعني أن الكمبيوتر لا يحتاج إلى شبكة خارجية. العميل وحده لا يحتوي خادم API أو PostgreSQL مضمنا في EXE.

## 2. شبكة LAN سلكية داخل المستشفى

```text
[Windows استقبال] ── Ethernet ──┐
[Windows مختبر]   ── Ethernet ──┼── [Gigabit Switch] ── Ethernet ── [خادم Mizan API + PostgreSQL]
[Windows صندوق]   ── Ethernet ──┤                         (10.10.20.10 مثال)
[Windows إدارة]   ── Ethernet ──┘
```

- استخدم Switch جيجابت وكابلات Cat6 أو Cat5e، وعناوين IP محلية ثابتة أو DHCP داخليا؛ هذه الشبكة لا تحتاج راوتر إنترنت.
- مثال فقط: الخادم `10.10.20.10` والشبكة `10.10.20.0/24`، مع منع الاتصال بالخادم من شبكات الضيوف.
- أنشئ شهادة TLS من مرجع داخلي موثوق، مع SAN يحتوي اسم الخادم الداخلي أو عنوان IP الذي يستخدمه العميل. وثق الشهادة على جميع أجهزة Windows؛ لا تستخدم قبول أي شهادة أو تجاوز التحقق.
- اضبط Kestrel ليستمع إلى واجهة LAN المحددة باستخدام شهادة الخادم، وافتح منفذ HTTPS الخاص بـ API للأجهزة المصرح لها فقط. PostgreSQL يبقى محليا على الخادم ولا يفتح مباشرة على محطات العمل.
- على كل جهاز Windows اختر «شبكة محلية سلكية LAN» واكتب رابط الخادم الفعلي، مثلا `https://10.10.20.10:5081` إن كان موجودا في SAN؛ ثم افحص الاتصال واحفظ.
- تحتاج أجهزة الموظفين اتصالا بالشبكة الداخلية **فقط**. لا تنشر API أو قاعدة البيانات على الإنترنت، ولا تفتح Port Forward.
- جهز نسخة احتياطية مشفرة مع اختبار استعادة، وUPS وخطة عمل عند انقطاع الكهرباء أو LAN.

## 3. تفعيل المسؤول الأول والهوية

- يتطلب الإنشاء الأول **قاعدة فارغة بلا مستخدمين** وعملية إعداد محلية على جهاز الخادم؛ رمز التهيئة قصير العمر ولا يمر إلى أجهزة LAN.
- يثبت الاسم رسميا كـ `HospitalIdentities` مع معرف ثابت `Id=1`. يتطابق اسم المستشفى عند تسجيل دخول جميع المستخدمين مع الاسم المحفوظ في الخادم؛ لا يمنح تغيير الاسم في مربع الدخول أي صلاحيات.
- لا يوجد حساب مسؤول افتراضي، ولا يُسمح بإنشاء مالك ثان عند وجود حسابات.
- للخدمة غير التفاعلية يستخدم المدير متغيرات `MIZAN_BOOTSTRAP_USERNAME` و`MIZAN_BOOTSTRAP_PASSWORD` و`MIZAN_BOOTSTRAP_HOSPITAL_NAME` **على الخادم فقط** قبل التشغيل الأول، ثم يحذف هذه القيم ويعيد تشغيل الخدمة. لا تُخزن كلمات المرور في Git.

## 4. صلاحيات الأقسام والصناديق

- المسؤول الأول يضيف الأقسام والمستخدمين ويحدد صلاحيات القراءة والإضافة والتقارير والمناوبات، ونطاق قسم واحد أو جميع الأقسام.
- صندوق الموظف مرتبط بمعرّف المستخدم وبالقسم. الزميل من القسم نفسه لا يفتح صندوق مستخدم آخر افتراضيا.
- مستخدم قسم واحد لا يرى بيانات الأقسام الأخرى، حتى عند استدعاء API مباشرة. بعض الحسابات المفوضة ذات النطاق العام تقرأ أقساما متعددة فقط ضمن الصلاحيات الممنوحة صراحة، ولا تتحول إلى مالك للنظام.
- يمنع من الخادم فتح صندوق أو فاتورة بقسم آخر دون تفويض. لا يكفي إخفاء الأزرار من العميل.

## 5. الانتقال من نسخة سابقة

لا تستخدم `EnsureCreated` بوصفه أداة لترقية قاعدة موجودة؛ فهو لا ينفذ الترحيل. الخادم سيمنع تشغيل حسابات قديمة تفتقد جدول `HospitalIdentities` أو اسما معتمدا، بدلا من إنشاء مالك جديد أو إعادة ضبط البيانات.

1. خذ نسخة مشفرة كاملة واختبر استعادتها على قاعدة تدريبية.
2. على القاعدة **التدريبية أولا**، نفذ `scripts/migrations/003-hospital-identity.sql` بعد مراجعة مسؤول قاعدة البيانات.
3. أنشئ سجلا واحدا فقط في `HospitalIdentities` بمعرّف `1` واسم المستشفى المعتمد بواسطة استعلام SQL معامل (parameterized)، ولا تضف سجلا افتراضيا.
4. اختبر تسجيل دخول المسؤول باستخدام اسمه واسم المستشفى وكلمة مروره الحالية وتأكد من بقاء السجلات والأذونات.
5. اعتمد ترحيلا مرقما ومراجعا لخادم الإنتاج قبل نقله، ولا تعالج تعارض المخطط بإسقاط الجداول أو مسح البيانات.

## 6. معايير القبول

- جهاز مستقل بدون إنترنت: تشغيل الخادم والعميل، وتفعيل المسؤول محليا، وتسجيل الدخول مع اسم المستشفى.
- جهازا LAN على شبكة Ethernet بلا إنترنت: الاتصال من المحطتين بالخادم عبر HTTPS موثوق.
- بيانات اسم مستشفى خاطئ: رد تسجيل الدخول `401` دون إصدار جلسة.
- حساب استقبال قسم A لا يستعرض مرضى وفواتير وصناديق قسم B، وزميل الصندوق لا يستخدم صندوق المستخدم الآخر.
- CI: Windows Core وWindows Release متوازيان، والاختبارات تسبق ملفات x86/x64 Portable وInstaller؛ كذلك يجب نجاح API Integration PostgreSQL.
- مراجعة أمان وترحيلات PostgreSQL وجهاز استعادة فعلي قبل الإنتاج.

# استعادة نسخ ميزان الطبي المشفرة — الاختبار الآمن

## ما أضيف
أداة C# مستقلة `MizanMedical.RestoreTool` تتعامل مع ملفات `.mizanbak` التي ينزلها المدير. تتحقق من:
1. وجود ملف SHA-256 ومطابقة البصمة.
2. صحة التشفير وكلمة المرور وسلامة كل كتلة وعلامة نهاية النسخة، **قبل** الكتابة إلى قاعدة البيانات.
3. عدم السماح بالاستعادة إلا إلى قاعدة اختبار مؤقتة ينتهي اسمها `_restore_test`، مع موافقة تشغيل صريحة عبر `MIZAN_RESTORE_CONFIRM=YES_DISPOSABLE`.
4. تمرير البيانات المفككة مباشرة إلى `pg_restore` عبر أنبوب ثنائي، دون إنشاء نسخة غير مشفرة على القرص.

## تشغيل تجريبي على خادم مختبر معزول
- جهز PostgreSQL client tools و.NET 10 وقاعدة جديدة فارغة `mizan_restore_test`.
- عيّن متغيرات الاتصال بـ PostgreSQL المناسبة: `PGHOST` و`PGPORT` و`PGUSER` و`PGPASSWORD`، مع مستخدم قاعدة اختبار فقط، دون أي صلاحية على قاعدة المستشفى الأصلية.
- عيّن `MIZAN_RESTORE_PASSPHRASE` بكلمة تشفير النسخة و`MIZAN_RESTORE_CONFIRM=YES_DISPOSABLE` داخل جلسة المشغل الخاصة، دون كتابتهما في ملفات أو GitHub.
- نفّذ: `dotnet run --project src/MizanMedical.RestoreTool -- /path/Mizan-Full.mizanbak mizan_restore_test`.
- تحقق من عدد الجداول وسجلات المرضى والفواتير والقيود ومطابقة إجمالي المدين والدائن. لا تعتمد النسخة دون اختبار الاستعادة.

## حدود الأداة
هذه الأداة **لا تستعيد قاعدة الإنتاج**، ولا تمنح صلاحية استعادة لمدير التطبيق عبر الشبكة، ولا تحذف البيانات أو تنشئ قاعدة تلقائيا.
يلزم إجراء إنتاجي منفصل معتمَد، وإيقاف العمليات المالية، ونسخة مستقلة قبل أي استعادة حقيقية.

## الاعتماد
اختبارات xUnit تغطي التشفير والفك وسلامة النسخة ومنع أسماء قواعد الإنتاج.
أضيف اختبار PostgreSQL في CI ينشئ نسخة مشفرة فعلية من API ويستعيدها إلى قاعدة `mizan_restore_test`، ثم يتحقق من عدد الأقسام وتوازن القيود. لا يعد ذلك إذنا لاستعادة قاعدة الإنتاج أو اختبارا لاستراتيجية التراجع الإنتاجية.

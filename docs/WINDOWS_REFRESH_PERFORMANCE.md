# تخفيض زمن تحديث شاشة Windows عبر شبكة المستشفى

## تغييرات تم تنفيذها
- مشاركة نتيجة طلب المرضى بين الجدول وقائمة إصدار الفاتورة **فقط** عند تطابق البحث والصفحة الأولى وحجم الصفحة. في بقية الحالات تظل الطلبات مستقلة لتجنب إظهار سجلات غير مطابقة.
- مشاركة نتيجة طلب الفواتير مع اختيار سند القبض عند تطابق الاستعلامات؛ تستمر تصفية المستحق من النتائج نفسها.
- بدء قراءة ملخص الصندوق الشخصي بالتوازي مع بيانات الأقسام والخدمات والمناوبات، بدلا من طلبها بعد انتهاء بقية البيانات.
- مهلة 25 ثانية لطلبات **GET التفاعلية فقط** بدلا من الانتظار حتى 30 دقيقة على انقطاع شبكة LAN. طلبات إنشاء الفواتير والتحصيل والصرف ونسخ قاعدة البيانات المشفرة لا تُلغى بهذه المهلة.
- إظهار زمن التحديث الفعلي في شريط الحالة، حتى يمكن قياس الأداء داخل المستشفى بأرقام فعلية لا افتراضية.

## معايير السلامة
- لا تخزين أو مشاركة نتائج بين المستخدمين أو الجلسات؛ إعادة الاستخدام داخل دورة التحديث الواحدة فقط.
- لا تجاوز لنطاق القسم أو الصلاحيات؛ كل طلب يعالجه الخادم بالصلاحيات نفسها.
- لا تغيير لمخطط PostgreSQL أو للنماذج المالية.
- حدود النتائج السابقة (100 افتراضيا مع البحث والتصفح) لا تتغير.
- القياس الحقيقي لأزمنة p95 تحت 10 و50 و100 موظف متزامن ما زال يتطلب منصة اختبار محلية ومقاييس من الشبكة.

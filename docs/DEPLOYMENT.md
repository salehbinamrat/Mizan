# التشغيل داخل شبكة مستشفى — تعليمات أولية للاختبار فقط

## المخطط

```
[جهاز استقبال Windows] ─┐
[جهاز الصندوق Windows] ─┼─ HTTPS/TLS ─ [خادم ميزان الطبي ASP.NET Core] ─ PostgreSQL على الخادم
[جهاز المحاسبة Windows] ┤
[جهاز الإدارة Windows] ─┘
```

كل مستخدم له حساب وصلاحية خاصة. لا توزع بيانات PostgreSQL على أجهزة المستخدمين. خصص خادما مركزيا ثابتا وUPS وخطة نسخ احتياطي، وافصل شبكة الإدارة عن شبكة الزوار.

## إعداد أولي للتجارب

- `dotnet --version` يجب أن يعرض إصدار 10.x.
- جهز PostgreSQL 17 أو إصدار مدعوم، بقاعدة بيانات UTF-8 جديدة وبيانات اعتماد ذات أقل صلاحية ممكنة.
- `MIZAN_DB_CONNECTION`: سلسلة اتصال Npgsql، مثلا `Host=127.0.0.1;Port=5432;Database=mizan_medical;Username=<user>;Password=<secret>`؛ لا تضع أسرارا داخل الملفات أو المستودع.
- **التهيئة التفاعلية الجديدة:** عند تشغيل الخادم يدويا في نافذة Console محلية على قاعدة جديدة تماما، وبدون متغيرات حساب المدير، يعرض الخادم رمز تهيئة عشوائيا. افتح تطبيق Windows على جهاز الخادم نفسه (عبر localhost)، واختر «تهيئة حساب مسؤول البرنامج لأول مرة»، وأدخل الرمز وبيانات حسابك. لا ينقل الرمز عبر الشبكة إلى بقية الأجهزة، ولا يخزن في ملفات المشروع. راجع [دليل التهيئة الآمنة](FIRST_RUN_OWNER_SETUP.md).
- **التهيئة غير التفاعلية (خدمات Windows):** استخدم `MIZAN_BOOTSTRAP_USERNAME` و`MIZAN_BOOTSTRAP_PASSWORD` مرة واحدة على الخادم إذا تعذر عرض المعالج، بكلمة مرور فريدة لا تقل عن 12 حرفا. احذف المتغيرين من بيئة الخادم بعد إنشاء المسؤول الأول وإعادة التشغيل.
- لا توجد بيانات دخول افتراضية. عند وجود مستخدمين بالفعل ولا يوجد حساب رئيسي، يتوقف الخادم ويتطلب إجراء استعادة إدارية مراقبا.
- `MIZAN_TIMEZONE`: المنطقة الزمنية، والافتراضي `Asia/Aden`.
- `MIZAN_CURRENCY`: رمز العملة، والافتراضي `YER`، ولا توجد ميزة تحويل العملات حاليا.
- `ASPNETCORE_URLS`: عنوان الاستماع على الخادم. للتجارب المحلية على جهاز واحد استخدم `https://localhost:5081` بعد إعداد شهادة التطوير؛ وللـ CI فقط يمكن تشغيل `http://127.0.0.1:5081`.

شغّل API للتطوير المحلي (جهاز واحد) بالأوامر:

```powershell
dotnet dev-certs https --trust
$env:ASPNETCORE_URLS = 'https://localhost:5081'
dotnet run --project .\src\MizanMedical.Api\MizanMedical.Api.csproj --no-launch-profile
```

في هذه الحالة يطابق العنوان القيمة الافتراضية في `mizan-client.json`. عند نقل العميل إلى أجهزة أخرى، لا تستخدم شهادة تطوير محلية غير موثوقة؛ أصدر شهادة باسم خادم حقيقي من جهة موثوقة داخل المؤسسة.

**النشر على LAN يتطلب HTTPS صحيحا.** استخدم اسم DNS داخليا وشهادة خادم من مرجع موثوق على أجهزة الموظفين، واضبط إعدادات شهادة Kestrel من مخزن أسرار الخادم (لا تعطل فحص الشهادات). لا يسمح الخادم بطلبات HTTP من غير loopback.

على كل جهاز Windows عدل الملف المجاور لبرنامج سطح المكتب `mizan-client.json`:

```json
{ "serverUrl": "https://mizan-hospital.example.internal:5081" }
```

هذا الاسم مثال فقط ويجب استبداله بعنوان DNS حقيقي يطابق الشهادة. اضبط الجدار الناري للسماح فقط للشبكة الإدارية بالوصول إلى منفذ API؛ لا تفتح PostgreSQL على أجهزة العمل.

## الصلاحيات في النسخة الأولية

| الدور | المهام المسموح بها |
|---|---|
| Admin | جميع الأقسام وإنشاء المستخدمين والصناديق |
| Manager | عرض التقرير المالي فقط |
| Accountant | المرضى والخدمات والفواتير والتقارير والمصروفات ومناوبة الصندوق |
| Cashier | المرضى والخدمات للقراءة والفواتير والمناوبات وسندات القبض |
| Receptionist | تسجيل المرضى وإنشاء فواتير الخدمات وقراءة الفواتير |

لا يسمح لموظف الاستقبال بإجراء تحصيل مالي أو تعديل أسعار الخدمات. مسؤولية المصروفات مقيدة بالمحاسب أو المدير، مع ضرورة مراجعة سياسة الموافقات قبل أي استخدام فعلي.

## مثال دورة اختبار

1. أدخل حساب مدير النظام، ثم أنشئ موظفا للاستقبال وموظفا للصندوق ومحاسبا.
2. أضف صندوقا رئيسيا وخدمة واحدة على الأقل بسعر تجريبي.
3. سجل مريضا وهميا، ثم أصدِر فاتورة تجريبية.
4. افتح مناوبة باسم المستخدم المخول، ثم حَصّل جزءا من الفاتورة.
5. أدخل مصروفا تجريبيا من حساب المحاسب مع مناوبته الخاصة.
6. أقفل المناوبة بعد عد النقدية فعليا، وراجع الفرق والقيود والتقرير اليومي.
7. جرّب إرسال أمر قبض مكرر بالمعرف نفسه، ومحاولة سداد مبلغ أكبر من المتبقي؛ يفترض ألا تنشئ عمليات إضافية.

## النسخ الاحتياطي (على الخادم فقط)

البرنامج **لا يملك نسخا احتياطية آلية مشفرة في هذه النسخة**. يوجد سكربت اختياري لعمل `pg_dump` على وسيط مشفر مسبقا مثل قرص BitLocker، مع بصمة SHA-256:

```powershell
# اضبط PGHOST وPGPORT وPGDATABASE وPGUSER والاعتماد السري خارج المستودع
$env:MIZAN_BACKUP_STORAGE_ENCRYPTED = 'YES' # فقط بعد التحقق الفعلي من تشفير وسيط التخزين
.\scripts\backup-database.ps1 -BackupDir 'E:\SecureMizanBackups'
```

اختبار الاستعادة يجري حصرا على قاعدة منفصلة تحمل اللاحقة `_restore_test`:

```powershell
.\scripts\restore-test.ps1 -BackupFile 'E:\SecureMizanBackups\mizan-sample.dump' -TargetTestDatabase 'mizan_restore_test' -ConfirmedDisposable
```

لا تشغّل الاستعادة على قاعدة المستشفى. لا تعتبر بصمة SHA-256 تشفيرا. تحقق من سلامة النسخة ونسخها خارج الخادم حسب سياسة معتمدة، واختبرها دوريا قبل التشغيل الحقيقي.

## معايير القبول قبل أي تشغيل فعلي

- نجاح اختبارات Windows Core وWindows Release واختبار PostgreSQL والتثبيت الفعلي لكل من x86 وx64.
- نجاح اختبار خمسة موظفين متزامنين على الأقل، والتزامن في التحصيل وإقفال الصندوق دون تكرار أو فقد بيانات.
- وجود ترحيلات قواعد بيانات قابلة للترقية والتراجع، وتوثيق خطة الاستعادة.
- تجارب فصل الشبكة والتعافي، وتنفيذ سياسة التشفير والمراقبة والسجلات والصلاحيات.
- مراجعة محاسب قانوني لقواعد المستشفى والسياسات الضريبية والفوترة؛ واعتماد الإدارة والجهة المسؤولة عن الخصوصية.

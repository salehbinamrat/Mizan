# Windows startup triage — ميزان الطبي

## العطل
قد يرى المستخدم أن التطبيق لا يفتح، بينما يستمر GitHub Actions في الإبلاغ عن نجاح البناء. السبب المحتمل في الإصدار السابق: إنشاء `HospitalApi` كحقل static في `App` وقراءة عنوان الخادم قبل ظهور نافذة WPF. أي JSON فاسد أو URL غير صالح كان يؤدي إلى استثناء في بداية تشغيل التطبيق، دون إرشاد للمستخدم.

كذلك تُوزع ملفات Windows كعميل فقط، وتحتاج إلى خادم ASP.NET Core وقاعدة PostgreSQL مركزية.

## الإصلاح
- تحميل إعدادات الخادم بطريقة آمنة: عند وجود JSON غير صالح يبقى التطبيق قابلا للفتح وتظهر رسالة تدعو لإصلاح العنوان.
- شاشة «إعداد اتصال الخادم» من صفحة الدخول، مع اختبار `GET /api/initial-setup/status` وزر حفظ في `%LOCALAPPDATA%\MizanMedical\mizan-client.json`، دون تعديل ملفات Program Files أو حفظ كلمات المرور.
- السماح بـ HTTP داخل loopback فقط، وإلزام HTTPS موثوق للاتصال عبر الشبكة؛ لا توجد وسيلة داخل البرنامج لتعطيل التحقق من TLS.
- تسجيل أخطاء التهيئة في `%LOCALAPPDATA%\MizanMedical\logs\startup.log`، مع نافذة خطأ في حالات WPF Dispatcher.
- اختبار `--startup-smoke` بلا اتصال شبكي، يحمّل بالفعل `LoginWindow.xaml` على Windows داخل النسخة المنشورة.
- Windows Release يفك ضغط Portable ويشغّل الاختبار، ثم يثبت Installer بصمت في مجلد مؤقت ويشغّل النسخة المثبتة، لكل من x86 وx64. أي فشل يمنع رفع وإقرار المخرجات.

## الحدود
لا يمكن لهذا الإصلاح تجهيز خادم المستشفى من تلقاء نفسه. يلزم إعداد API وPostgreSQL وشهادة HTTPS موثوقة على الجهاز المركزي، وفقا لدليل `docs/DEPLOYMENT.md`. اختبار التهيئة آلي، وليس اختبارا تفاعليا على جهاز المستخدم؛ إذا تكرر الإغلاق يحدد السجل نظام Windows وملف الخطأ الذي يجب إصلاحه.

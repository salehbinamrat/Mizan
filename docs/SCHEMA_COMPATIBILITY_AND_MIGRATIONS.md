# فحص توافق قاعدة بيانات ميزان الطبي قبل التشغيل

## الإصلاح
الخادم بعد إنشاء قاعدة جديدة (في بيئة التطوير الأولية) يفحص وجود الأعمدة الأساسية لجميع جداول الأقسام والمستخدمين والصناديق والفواتير والقيود والتدقيق، **قبل** السماح بتهيئة حساب المسؤول أو أي إجراء مالي. إذا وُجد مخطط قديم أو قاعدة مختلفة، يتوقف بخطأ واضح؛ لا يعيد إنشاءها ولا يضيف بيانات فوق مخطط جزئي.

## الحدود
- هذا **فحص توافق** وليس تنفيذا كاملا لترحيلات EF Core؛ ما زال `EnsureCreatedAsync` يستخدم فقط لإنشاء قاعدة جديدة، ويجب استبداله في مرحلة مراجعة الهجرة بخطة إصدار مرقمة.
- لا تنفذ `002-department-limits-personal-desks.sql` على قاعدة الإنتاج دون نسخة احتياطية مستعادة ومراجعة لتوافق المخطط على قاعدة تجريبية.
- لا تقم بترقية تلقائية لقاعدة مستخدمة أثناء دوام المستشفى. ضع خطة إيقاف ونسخ احتياطي وتراجع مع مدير النظام، وافحص الأرصدة والقيود بعد كل ترحيل.
- فحص الأعمدة يمنع بعض حالات عدم التوافق، لكنه **لا يثبت** مطابقة القيود والفهارس وأنواع الأعمدة والإصدارات؛ أضف فحصا أعمق مع إصدار المخطط قبل الاعتماد الإنتاجي.

## الاختبارات
تتحقق اختبارات C# من كشف القاعدة القديمة وعدم قبول قاعدة لا تخص ميزان الطبي. اختبار تكامل PostgreSQL على قاعدة جديدة يتحقق من قدرة الخادم على الإقلاع؛ ما زال اختبار ترحيل نسخة قديمة إلى مخطط جديد مطلوبا.

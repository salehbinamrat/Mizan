# ميزان الطبي — شاشة تسجيل الدخول الموحدة

## نطاق المرحلة
شاشة واحدة لجميع مستخدمي المستشفى (مسؤول البرنامج، المسؤول العام، مدير القسم، المحاسب، أمين الصندوق، والاستقبال).

1. يكتب الموظف اسم المستخدم وكلمة المرور فقط. لا يختار قسما حتى لا يتمكن من انتحال قسم آخر.
2. يتحقق خادم ASP.NET Core من الحساب، حالة التفعيل، قفل المحاولات، الجلسة، ونطاق القسم.
3. بعد إنشاء الجلسة يقرأ العميل `GET /api/auth/me` مرة أخرى لتثبيت الصلاحيات الحالية من الخادم بدلا من الثقة ببيانات الواجهة.
4. يسمح البرنامج بعرض التبويبات المتوافقة حصرا مع الصلاحيات؛ نوع الحساب يحدد صفحة البداية فقط، ولا يمنح صلاحية إضافية.
5. حساب أمين الصندوق ينتقل افتراضيا إلى صفحة الصندوق إذا كان مفوضا، والاستقبال إلى المرضى، والمدير صاحب التقارير إلى الرئيسية. حساب بدون صلاحيات تشغيلية لا يفتح صفحة فارغة.
6. المستخدم المرتبط بقسم واحد لا يستطيع تغيير القسم من واجهة البرنامج. المسؤول المصرح له بكافة الأقسام يستطيع تحديد قسم للإجراءات، لكن الخادم يبقى مصدر القرار النهائي.
7. عند تحديث البيانات، يُعاد جلب صلاحيات الحساب الحالية. تعديل المسؤول لصلاحيات أو تعطيل موظف يبطل جلساته المخزنة، بما يتطلب الدخول مجددا.
8. الصندوق الشخصي لا ينشأ من اختيار الموظف في صفحة الدخول؛ ينشئه المدير والخادم وفق حساب المستخدم. عمليات القبض والصرف والتحويل مقيدة بالصندوق المخول.

## الأمان
- إخفاء التبويبات **ليس** إجراء الحماية الوحيد: يجب استمرار التحقق من نطاق القسم والصلاحية على كل API.
- لا تسجل كلمات المرور أو رموز الجلسات في السجلات أو الروابط أو ملفات الإعداد.
- رسائل الخطأ الخاصة بفشل الدخول لا تفصح عما إذا كان اسم المستخدم موجودا.
- يجب اختبار موظفين من قسمين مختلفين ومدير عام وأمين صندوق وحساب بدون صلاحيات، بالإضافة إلى إبطال الجلسات.

## شروط الدمج
اختبارات xUnit أولا، ثم Windows Core وWindows Release بالتوازي؛ بعد اختبارات الإصدار الناجحة يتم بناء x86/x64 Portable وInstaller. اختبار PostgreSQL شرط مستقل. لا دمج عند وجود فشل.

# ميزان الطبي | Mizan Medical Finance

**الحالة:** هيكل تنفيذي تجريبي للمرحلة الأولى (0.1.0)، وليس نظاما معتمدا للتشغيل المالي الحقيقي بعد.

تطبيق Windows متعدد الأجهزة والمستخدمين مع خادم ASP.NET Core وقاعدة بيانات PostgreSQL مركزية. جميع طلبات العمل تتم عبر API محمي بدخول المستخدم وصلاحياته؛ لا تتصل أجهزة الموظفين بقاعدة البيانات مباشرة.

## مكونات المشروع

```
src/MizanMedical.Domain     قواعد مبالغ مالية، توازن القيود، تجزئة كلمات المرور
src/MizanMedical.Api        خادم مركزي، مصادقة، صلاحيات، واجهات مالية، EF Core/PostgreSQL
src/MizanMedical.Desktop    برنامج Windows WPF عربي
 tests/MizanMedical.Tests    اختبارات xUnit لوظائف الدومين
scripts/                     اختبارات تكامل، بناء 4 نسخ Windows، نسخ احتياطي
installer/                   مُثبت Inno Setup
.github/workflows/           Windows Core + Windows Release + اختبار تكامل PostgreSQL
```

## الوظائف المنفذة في الهيكل الأولي

- إنشاء مدير عند التشغيل الأول فقط، وإضافة حسابات الموظفين ومنح الأدوار.
- تسجيل دخول بجلسة مؤقتة 8 ساعات، رموز جلسات مخزنة على الخادم كـ SHA-256، وPBKDF2 لكلمات المرور، وتحديد محاولات الدخول الفاشلة.
- تسجيل مرضى بحد أدنى من البيانات، وتعريف الخدمات والأسعار والأقسام.
- إصدار فاتورة متعددة البنود مع سعر خدمة يحدد من قاعدة البيانات فقط، ولقطة محفوظة من سعرها وقت الإصدار.
- قبض دفعات جزئية دون تجاوز رصيد الفاتورة؛ منع التكرار بتعريف طلب فريد.
- فتح مناوبة صندوق وربط المقبوضات والمصروفات بها، وإقفالها مع مطابقة الرصيد وتوثيق الفرق.
- تسجيل مصروفات نقدية من حساب محاسب أو مدير مع مناوبة يملكها، ومنع الصرف فوق الرصيد المتاح.
- إنشاء قيود قيد مزدوج أولية (ذمم مرضى/إيراد/نقد/مصروف)، مع سجل تدقيق أساسي.
- تقرير يومي للفواتير والمقبوضات والمصروفات، وتصدير CSV قابل للفتح في Excel، والطباعة أو اختيار Microsoft Print to PDF.
- حماية قاعدة البيانات المركزية من وصول المستخدمين المباشر؛ تحققات مالية على الخادم، ومعاملات `Serializable` للعمليات المالية.
- مسارا Windows Core وWindows Release متوازيان، مع اختبارات قبل التعبئة وإنتاج أربع نسخ على Windows CI.
- سكربت نسخ احتياطي بملف PostgreSQL مخصص، مع تجزئة SHA-256 واشتراط وجهة تخزين مشفرة مسبقا؛ واختبار استعادة فقط إلى قاعدة تجريبية.

## ما لم يكتمل بعد (لا تستخدم بيانات مالية أو مرضى حقيقية)

- **بناء وتجربة فعلية على Windows:** لم تُنفذ في بيئة إنشاء هذه الحزمة لغياب .NET SDK وWindows؛ يجب تشغيل GitHub Actions ومعالجة أي فشل قبل التجربة.
- ترحيلات قاعدة بيانات مرقمة `EF migrations`، وخطة الترقية دون فقد بيانات؛ حاليا `EnsureCreated` فقط لإنشاء القاعدة عند أول تشغيل.
- اختبارات تكامل ومعايرة الأداء المتعدد الأجهزة في شبكة مستشفى حقيقية، والاختبارات الطرفية للواجهة والصلاحيات.
- اعتماد الفواتير، الإلغاءات والمرتجعات وتسوياتها المحاسبية، وحدود موافقة المصروفات وسير الموافقات.
- التأمين الطبي، حسابات الموردين، الرواتب، الضرائب المعتمدة محليا، دفتر الأستاذ العام الكامل، إقفال الفترات وميزان مراجعة رسمي.
- تشفير بيانات المرضى عند التخزين حسب سياسة المستشفى، وتدوير المفاتيح، والمراقبة التشغيلية والتنبيهات.
- اختبار الاستعادة الدوري، والنسخ الآلي بجدول معتمد، ومراجعة الصلاحيات، واختبار انقطاع الشبكة وإعادة محاولة العمليات.
- إعدادات المؤسسة المتعددة والعملات وإدارة أسعار الصرف، وفواتير طباعة تفصيلية بالهوية المعتمدة.

## البداية

اقرأ [دليل التشغيل المحلي](docs/DEPLOYMENT.md) قبل التشغيل.

1. ثبّت .NET 10 SDK وPostgreSQL 17 على خادم الاختبار، و.NET 10 SDK مع Windows SDK على جهاز تطوير الواجهة.
2. أنشئ قاعدة PostgreSQL مستقلة للتجارب، وأعد إعداد متغيرات الاتصال وكلمة مرور مسؤول أول مرة (لا تحفظها في Git).
3. في خادم التطوير اضبط HTTPS لشبكة المستشفى؛ ويسمح HTTP فقط عند التشغيل من localhost للاختبارات.
4. نفّذ `dotnet run --project src/MizanMedical.Api` على الخادم ثم `dotnet run --project src/MizanMedical.Desktop` على جهاز Windows.
5. أنشئ الصناديق والخدمات والموظفين من تبويب الإدارة، ثم اختبر دورة الفاتورة والمناوبة على بيانات وهمية.

## بناء Windows

على GitHub Actions تحقق من نجاح وظائف `Windows Core` و`Windows Release` و`API Integration PostgreSQL`، ثم استخرج:

- `MizanMedical-win-x86-Portable.zip`
- `MizanMedical-win-x86-Installer.exe`
- `MizanMedical-win-x64-Portable.zip`
- `MizanMedical-win-x64-Installer.exe`

**مهم:** النسخ الأربع تخص عميل Windows؛ يلزم نشر خادم API وقاعدة PostgreSQL منفصلين داخل المستشفى.

لا تدمج PR في `main` حتى تنجح وظائف CI جميعها. فعّل قواعد حماية الفرع يدويا داخل إعدادات المستودع، لأن ملف workflow وحده لا يمنع الدمج.

## متابعة سلامة المالية والأدوات

راجع [اختبارات حدود القيود واحتياجات الأدوات](docs/PHASE1_SAFETY_AND_TOOLING.md). التعديلات لم تخضع لتشغيل .NET SDK، ولا تستخدم للإنتاج قبل CI والمراجعة.

## الإدارة والصلاحيات بحسب الأقسام (تطوير تجريبي)

أضيفت شاشة مستقلة لإدارة الأقسام والموظفين وصلاحيات كل إجراء، مع عزل الخادم للمعلومات المالية بحسب القسم. حساب التهيئة الأصلي وحده ينشئ المستخدمين ويمنح نطاق كل الأقسام. راجع [تفاصيل الصلاحيات والاختبارات وحدود النشر](docs/DEPARTMENT_ACCESS_CONTROL.md).

> **مهم:** هذه تعديلات على مخطط قاعدة البيانات وليست Migration معتمدة. لا تحدّث قاعدة مستشفى قائمة باستخدام `EnsureCreated`، ولا تدخل بيانات حقيقية قبل تشغيل الاختبارات ومراجعة الترحيل والأمان.

## إعداد مسؤول البرنامج لأول مرة

يمكن إنشاء المسؤول الأول عبر [معالج تهيئة Windows المحلي](docs/FIRST_RUN_OWNER_SETUP.md) على جهاز الخادم في تشغيل تفاعلي، باستخدام رمز مؤقت يظهر على شاشة الخادم؛ أو عبر متغيرات بيئة الخادم في التشغيل غير التفاعلي. لا يوجد حساب افتراضي، ولا يُسمح بإعادة التهيئة على قاعدة تضم مستخدمين. لا تُستخدم الميزة بعد للإنتاج دون التحقق من الشبكة وقاعدة البيانات على خادم المستشفى.

## الهوية البصرية وأيقونة Windows

صُممت أيقونة أصلية تحمل حرف M مع الصليب الطبي والميزان المالي وتخطيط القلب، بألوان كحلية وفيروزية وفضية. الملفات موجودة في `src/MizanMedical.Desktop/Assets/`:
- `MizanMedical.ico` أيقونة متعددة المقاسات 16/24/32/48/64/128/256 لتطبيق Windows وشريط المهام وملف Installer واختصاراته.
- `MizanMedical-UI.png` للشاشات الرئيسية وصفحة الدخول وتهيئة المدير الأولى.

تُحمّل ملفات الأيقونة كموارد WPF مضمّنة في التطبيق لتعمل دون إنترنت، ويستخدم Inno Setup الأيقونة نفسها أثناء بناء 32-bit و64-bit. يتأكد اختبار `ApplicationIconContractTests` من وجودها وربطها بالمصادر والإصدار. جميع ملفات الأيقونة أصلية ولا تعتمد على صور أو شعارات خاصة بمستشفى آخر.
